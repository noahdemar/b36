# B-36 Multicrew - Project Spec

In-browser game for multicrew B-36 Peacemaker missions. The 3D model is the core asset.

## Decisions (confirmed with user, 2026-10-18)

| Topic | Decision |
|---|---|
| 3D model source | Blender-authored glTF, generated by Python scripts (headless `bpy` via uv) |
| Interior | Full walkable interior: forward compartment, tunnel + trolley, aft compartment |
| Networking | Single-player first: one player can switch between all stations. Networking later |
| Fidelity | Moderate: believable flight model, engine management, nav, radar bombing, gunnery |
| Variant | B-36H (proposed): full defensive armament gives gunner stations. Confirm with user |

## Architecture

```
b36/
  SPEC.md
  tools/model/        uv project; bpy scripts that generate the aircraft
    params.py         all dimensions, each tagged SOURCED / DERIVED / ESTIMATED
    build_b36.py      generates the scene and exports web/public/models/b36.glb
    render_previews.py  Cycles CPU renders for review
  web/                Vite + TypeScript + three.js client
```

- Model is fully procedural and parametric: change params.py, regenerate, reload.
- Coordinates (Blender): +Y forward (nose), +X right wing, +Z up, meters. Origin at fuselage
  centerline, mid-length. glTF export converts to Y-up with nose toward -Z (three.js forward).
- Animated parts are separate nodes with origins on their hinge/rotation axis and local X aligned
  with the hinge: ailerons, flaps, elevators, rudder, 6 props, bomb bay doors, turrets, gear.
- Naming convention for nodes: `Prop_L1..L3/R1..R3`, `Aileron_L`, `Flap_R2`, `Elevator_L`,
  `Rudder`, `BombDoor_B1_L`, `Turret_*`, `Gear_*`. The client looks parts up by name.

## Reference data

Sourced (NMUSAF via Wikipedia, B-36J-III spec block):
- Length 49.40 m, span 70.10 m, height 14.25 m, wing area 443.3 m2
- Airfoil NACA 63(420)-422 root, 63(420)-517 tip
- Max wing thickness 7.5 ft (2.3 m) -> root chord derived as 2.3 / 0.22 = 10.4 m
- Dihedral 2 deg, incidence 3 deg, washout 2 deg
- 6x R-4360 pusher, 3-blade 19 ft (5.8 m) props; 4x J47 in 2 pods outboard of piston engines
- Crew 15 (H model), forward and aft pressurized compartments joined by tunnel with trolley
- 4 bomb bays
- Fuselage diameter: one text source says 3.5 m; the three-view measures 3.75 m (used)

Measured from the General Dynamics three-view (reference/MEASUREMENTS.md): fuselage profile
(3.75 m dia), canopy, wing planform, nacelle/jet pod stations, fin contour, tailplane planform.
Verified by tools/model/compare_blueprint.py overlays.

Still estimated: gear geometry, turret positions, bomb bay stations, control surface spans,
jet pod length and drop.

## Interior: flight deck (phase 3, started 2026-10-18)

Decisions (confirmed): pilot station first; cockpit + flyable; clickable 3D cockpit with keyboard
shortcuts; keyboard + mouse input; layout reference-matched.

References: reference/cockpit/ (USAF walkaround photos via cybermodeler.com, NMUSAF flight deck
photo, B-36 flight manual Fig 1-3 "Forward Cabin Arrangement").

Layout (manual Fig 1-3 + photos):
- Raised flight deck under the canopy. Left seat = Aircraft Commander (first playable seat),
  right seat = Pilot. Flight engineer behind the right seat at a large panel. Lower deck
  ahead/below: navigator, radar observer, nose sight; radio operator aft.
- Main panel under a padded arc glareshield. Left: AC flight instruments (ASI, attitude, RMI,
  altimeter, VSI, turn & slip, radio altimeter, manifold pressure, RPM, clock). Center: 4x4 J47
  gauges (RPM %, EGT, fuel press, oil press) under six reversed-prop lights. Right: pilot
  flight instruments.
- Pedestal: 6 piston throttles T1-T6, gear switch, flap switch, nose wheel steering switch,
  parking brake, trim. Overhead: jet engine control panel with 4 jet throttles.
- Yokes: ram's-horn on floor columns. Nose wheel steering tiller on left console.
- Colors: black panels and frames, interior green structure, green seat cushions.

Implementation:
- tools/model/build_interior.py -> web/public/models/b36_interior.glb, same coordinates as
  exterior. Canopy is integrated into the fuselage loft (hump + glazed faces + frames) so the
  inside and outside glazing match.
- Instruments: bezel + dial face (PIL-generated texture atlas) + named needle nodes;
  extras give instrument id and needle index. Mapping value -> angle lives in the client.
- Controls: named nodes with extras {control, axis, min, max}; client raycasts and drags.
- Flight model in the client: 6DOF rigid body, aero coefficients derived from published
  performance (each tagged in code as DERIVED/ESTIMATED), validated by scripted tests.

Status (2026-10-18): first playable pilot station.
- Run: `cd web && npm install && npm run dev`, open the printed URL. Keys: H shows the help panel.
- Flight model: web/src/sim/. `node --experimental-strip-types src/sim/perf_test.ts` checks
  performance vs published figures (vmax 435 mph = pub 435; ceiling 45,600 ft vs pub 43,600; SL climb
  2,457 ft/min at 262,500 lb vs pub 1,995, condition unstated). `stability_test.ts` checks
  hands-off and control response.
- Verified in headless Chromium: loads both GLBs, cockpit renders, scripted takeoff, picking/drag of
  throttles and the gear lever.
- Known gaps: seats and controls are low-poly; interior lighting is flat (no baked AO); no panel
  lighting at night; tiller and trim are wired but not tuned; jets have no start sequence.

## Crew movement (started 2026-10-18)

User request: foundation for moving around inside the aircraft; keep the current flight controls.
- Modes: seated (at a station), walking, climbing (ladder), outside camera.
- Data: build_interior.py writes web/public/models/b36_nav.json in model coordinates (three.js:
  x right, y up, z aft, origin mid-length): floor rects per deck, obstacle AABBs, ceiling grid per
  deck (headroom under the curved hull), ladders, seats (sit eye point, facing, stand point).
- Client: src/crew.ts controller in aircraft-local coordinates (no inertial effects yet).
  Walking: WASD, right-drag look, Shift faster, C-key stays camera toggle. E or click: sit / use
  ladder. X: stand up. Flight inputs only reach the sim from the AC and pilot seats.
- Scope now: forward compartment, both decks, ladder, placeholder lower-deck stations.
  Next: forward entrance hatch, the 85 ft tunnel with trolley, aft compartment.

## Quality target: "War Thunder" level (user, 2026-10-18)

Long-term target for exterior and interior. Gap list, in planned order:
1. Surface: UV layout, baked AO, panel-line and rivet normal maps, natural-metal panel variation,
   insignia and markings (decals), weathering. (Biggest visible gain.)
2. Geometry detail: cowl flaps and cooling exits, exhaust and turbo outlets, nacelle intakes

## Weapons, stations and realism pass (requested 2026-10-18)

Decisions (confirmed): turrets aimed/fired from the real B-36H gunner stations (so the tunnel and aft
compartment are built now); ground targets only (bombing range + ground gunnery targets); flight
engineer gets engine management.

Order of work:
1. Airframe surface: analytic UVs on the procedural lofts; generated textures (panel lines, rivet
   rows, per-panel natural-metal variation, insignia and lettering, light weathering) as color,
   normal and roughness maps; more geometry detail. Textures ship as separate image files.
2. Autopilot (altitude + heading hold) so the crew can leave the pilot seats.
3. Bombs: loads in 4 bays, door control, radar observer / bombardier station with sight and
   release (single / train / salvo), ballistic bombs with drag, impacts, bombing range with targets.
4. Turrets (B-36H, 8 turrets, 16 x 20 mm): extend/retract, slew limits and rates, fire with tracers.
   Gunner stations: nose (bombardier sight), upper forward L/R (forward compartment blisters),
   upper aft L/R and lower aft L/R (aft compartment blisters), tail (radar gunner, aft compartment).
   Tunnel with trolley from the forward compartment aft bulkhead to the aft compartment.
5. Flight engineer: per-engine throttle, mixture, prop rpm, turbo boost, cowl flaps, ignition and
   start, CHT / oil temp model, fuel tanks and consumption.
6. Navigator chart with live position; APS-23 radar scope for the radar observer.

Status (2026-10-18): steps 1-6 done; all six have headless tests or browser checks.

### Engine management (web/src/sim/powerplant.ts, test: src/sim/engine_test.ts)
- Per engine: running / failed, starter (cranks to 280 rpm, catches after 3 s with ignition, mixture
  not cutoff and fuel), rpm lever 1200-2700 (governor), turbo boost selector (critical altitude
  1,500 m at 0 to 10,700 m at 1), mixture cutoff / auto-lean / auto-rich, cowl flaps, feathering,
  windmilling drag when stopped. Power law is the fitted one from perf_test times these factors, so
  published performance is unchanged at default settings (re-measured: 435 mph at 36,089 ft).
- CHT and oil temperature are first-order models (tau 60 s / 180 s) driven by power and cooling
  (cowl flaps, airspeed); red line 260 C, failure after about 20 s above 280 C. All ESTIMATED.
- Fuel: B-36H capacity DERIVED as 36,396 gal (B-36J) - 2,770 gal (J outer-panel tanks) = 33,626 gal;
  6.0 lb/gal (30,600 gal = 183,600 lb). Eight wing tanks (outboard, center, inboard, aux per side,
  split ESTIMATED) plus a bomb bay tank not fitted with bombs aboard. Fuel at combat weight DERIVED:
  262,500 - 165,887 empty - 48,000 bombs - 3,000 crew - 6,000 stores = 39,613 lb. BSFC 0.55 rich /
  0.45 lean, J47 TSFC 1.0 (ESTIMATED). Manifold per side with tank selector and crossfeed; fuel
  burn lowers mass; side imbalance gives a rolling moment.
- Automatic engineer (cowl flaps toward 215 C, tank sequencing) runs unless a player sits at the
  FE seat; it comes back when they leave. Shift+R resets cold and dark.
- FE panel: 6 x 5 engine gauges (rpm, MAP, CHT, oil temp, fuel flow) and two fuel quantity
  gauges, all driven from the sim. Arrangement ESTIMATED.

### Navigator and radar (web/src/stations.ts)
- Chart on the navigator's table (CanvasTexture; V for full screen): grid, runway, range, targets,
  track history, waypoints (base, IP, target, or click), leg data, fuel endurance and range.
  Enter couples the autopilot heading to the waypoint.
- APS-23 PPI on the radar console (B for full screen): heading-up, 10/25/50/100 mi, 20 rpm scan,
  2.5 deg beam, phosphor persistence, altitude hole, noise ground clutter, dark runway, strong
  target returns, predicted bomb impact cross for radar bombing. Scan rate, beam and ranges
  ESTIMATED.

Sources: warhistory.org/es/@msw/article/convair-b-36 (J capacity, outer tanks);
aeroantique.com B-36H outboard wing tank gauge listing (9 tanks); armedconflicts.com/-t15718
(B-36H empty weight); amc.af.mil Article 147245 ("more than 183,000 pounds" of fuel).

## Damage and interior realism (requested 2026-10-18)

Decisions (confirmed): damage from flak over the target, mechanical failures, and overstress / hard
landings / crashes (no fighters for now); component-based damage model (War Thunder style); interior
realism pass starts with the flight deck. Requirement: the aircraft can take a beating before going down.

Damage model (web/src/sim/damage.ts):
- Components with hit points and positions in model coordinates: 6 engines, 4 jets, 9 fuel tanks,
  wing sections (inner / outer per side), fuselage (fwd / mid / aft), fin + rudder, stabilizers +
  elevators, ailerons, flaps, gear legs, turrets, control cables.
- Effects: engine fire (spreads to the wing section, FE extinguisher), oil leak -> seizure, power loss;
  tank leaks and fires; lift / drag / control effectiveness loss per section (asymmetric); cables cut;
  gear collapse; structural failure (wing or tail separation) when a section's HP reaches 0.
- Sources: flak batteries around the range (predicted fire with range-dependent error, fragment
  hits by distance and part area), random failures raised by engine abuse (CHT, overspeed), load
  factor above limit, overspeed, hard or gear-up landings, ground strikes.
- Feedback: crew calls, FE damage panel, pilot warnings, smoke / fire trails, hole decals,
  separated parts. Crash = destroyed; R resets.

Status (2026-10-18): damage model done (web/src/sim/damage.ts, flak.ts, damagefx.ts; tests
sim/damage_test.ts, flak_test.ts). Measured: bursts needed to lose the aircraft (20 seeds): median 9 at
15 m, 33 at 30 m, 125 at 50 m. One pass over the range (12 runs each, flak error 30 m + 1.5% of slant
range): 12,000 ft lost 0/12, 0.33 engines per pass, median worst part 62%; 25,000 ft 0/12, 83%;
40,000 ft untouched. Wing tip (outboard of 28 m, through the aileron) can be shot off and the aircraft
stays flyable (autopilot holds altitude with 0.49 aileron); main wing, center/forward fuselage or aft
fuselage failure loses the aircraft. Limits used: 2.0 g limit / 3.0 g ultimate, 330 mph IAS Vne,
gear 10 / 16 / 25 ft/s sink (damage / collapse / crash), all ESTIMATED. FE fire bottles: B key.
The autopilot's pitch loop now uses low-passed alpha (it oscillated 0.2-2.0 g near the ceiling).

Interior realism (tools/model/build_interior.py):
- Flight deck first: modeled seats (frame, cushions, belts, armor), consoles with switches and
  labeled placards, textured materials (painted metal, crackle-black panels, wear), baked ambient
  occlusion, panel / cabin lighting; then FE station, lower deck, tunnel, aft compartment.

Interior status (2026-10-18): tiled PBR materials (interior_textures.py: worn black paint, clean panel
paint, grey-green paint, olive canvas, khaki webbing, quilted black sound-proofing, floor), box-projected
UVs, 2048 px AO lightmap baked in Cycles (16 spp, 0.5 m, ~5.5 min) exported as the glTF occlusion map on
TEXCOORD_1; modeled crew seats (cushions, armoured reclined back, armrests, harness); placard overlays
(placards.py) on the main panel, pedestal, overhead and consoles; pedestal and console knobs and
toggles; oxygen regulator panels; cabin shadows (interior meshes cast and receive, tight 8 m sun
shadow frustum when inside) and a cabin environment map lit only through the glazing.
Camera guard (user, 2026-10-18: "Player camera should never go outside/clip with the plane"): nav JSON
carries the inner hull profile; Crew.clampToHull keeps the walking / climbing eye 14 cm inside the
skin (crew_test checks seat eyes and random walks). Tunnel hatches are real openings with open doors,
clickable (extras.tunnel), E range 1.3 m, and a "hatch ahead" hint within 4 m.

## Tunnel, turret clipping, gunnery and fighters (2026-10-18, session 2)

Root causes found and fixed:
- Tunnel: entering at the forward hatch put the crew member at s = 0 on the tunnel path, and the next
  frame treated that as "pulled out of the forward end" unless W was already held, so E bounced the
  player straight back out. Now the crew member leaves only by pulling outward past an end.
  The walkway past the engineer's panel was a 10 cm slalom (panel moved inboard edge 0.05 -> 0.20 m,
  crew radius 0.24 -> 0.20 m). crew_test has a player-style route (limited turn rate, aim noise,
  sloppy waypoints, E, W through the tunnel) and auto-walk to every seat.
- Click-to-walk: clicking a seat, ladder or hatch from up to 12 m walks there (A* on a 5 cm grid per
  deck, then line-of-sight shortcuts); Tab lists all stations and walks there through ladder/tunnel.
- Turret clipping: retractable turrets are clipped by a plane 0.09 m below the extended ring (inside
  the outer skin, outside the cabin lining), so moving or extended turrets never show inside.
  The vertical fin root (FIN_ROOT_Z 1.2) hung up to 0.6 m into the aft compartment ceiling; fin
  vertices inside the fuselage are now raised to 2 cm under the skin (build_b36.seat_on_hull).

Gunnery (user decision: enemy fighters, no lead marker in third person):
- MiG-15bis (SOURCED: span 10.08 m, 1,076 km/h SL, 990 km/h at 10 km, N-37D 40 rds 400/min,
  2 x NR-23 80 rds each). Attack geometry, g, aim error, damage per hit ESTIMATED. Passes from
  set-up points at clock positions, lead pursuit, break, extend, repeat; damaged fighters may leave.
- AI gunners on every turret the player does not man (aim error 20 mil wandering, 20% ranging
  error, 2.5 s reaction, bursts). Measured (fighters_test, 4 MiGs, 3 min, 32,000 ft, 6 seeds):
  undefended 70 passes, bomber lost 2/6; with AI gunners 0/6 lost, 11/24 fighters downed.
- Computing sight: tracking rate + range rate (inertial frame) -> lead solution (drag, drop, trail;
  ballistics.ts, gunnery_test misses < 1 m). Ranging ring of diamonds for a MiG's span (wheel),
  tail station radar lock, G range assist (game aid). Crossing fighter at 500 m, perfect tracking:
  75 hits / 190 rounds with correct range, 2 with a fixed 600 m setting, 0 aiming straight at it.
- Bug fixed: rounds were stepped once on the frame they were fired, running 1/60 s ahead of the
  target (about 4 m at 250 m/s closure); hit rates were 4x too low.
- Barrel heat, stoppages and charging, per-gun ammunition, slewing/limit/interrupter status,
  muzzle flash, smoke, cases, recoil, sight vibration, procedural sound (audio.ts).

Third person (user decision: mouse aim for the pilot):
- C at a pilot seat: chase camera; the mouse sets an aim direction, sim/instructor.ts flies there
  (bank 30 deg, flight path -12..+10 deg, 1.7 g protection, takeoff rotation). instructor_test:
  turns, climbs, dives, pull-out 0.87-1.60 g, takeoff, no damage. W/S/A/D override, M toggles.
- C at a gun station: camera behind/above the aircraft along the gunner's line of sight; the sight
  line is laid through the crosshair point at the set range.

World (user priorities: sky and clouds, terrain, station interiors):
- terrain.ts: quadtree chunks (32x32, leaf 1.6 km, root 410 km), flat plain within 24 km of the
  runway-range line (bombs, rounds and flak use y = 0), hills to 520 m, mountains to 3.6 km beyond
  55-95 km; flying into terrain is a crash. Shader land use: field patchwork per 7 km region,
  hedgerows, forest, rivers, lakes, towns, rock, snow.
- clouds.ts: cumulus from camera-facing puffs with flat bases, lit tops, sun rim; cirrus at 9.8 km.
- Contrails from the six pistons, four jets and fighters below 235 K (ISA ~8,200 m, ESTIMATED).
- Time of day (Shift+T): sun for 35 N, +20 deg declination; sky, fog, light colours, env map.
- Interiors: equipment units (meters, knobs, toggles, lamps, handles) on the radio rack, K-system
  rack, radar and tail consoles; bombing switch box; navigator's instrument panel and chart lamp;
  cable runs; oxygen cylinders; extinguisher; station lights. Paint chip wear reduced.

Open: fighter visuals are low poly; no cloud shadows on terrain; sound is synthesized (no samples);
radio operator station not functional.

## Multiplayer multicrew (requested 2026-10-19)

Decision (user): hosted locally, friends join by IP. No public hosting for now.

Architecture: one authoritative simulation, everyone else renders it.
- `web/server/server.ts` (Node): the host runs it on their machine. It serves the built game and a
  WebSocket at /ws on port 8036 (0.0.0.0). It is a relay: it assigns player ids, passes player input
  to the host and the host's snapshots to everyone. Friends open http://<host-ip>:8036.
- The host's browser (the first connection from the host's own machine) runs the full sim exactly as in
  single player (flight model, systems, damage, flak, fighters, AI gunners) for the whole crew. Remote
  players' key presses, held keys, mouse yoke, gun sight direction and cockpit lever commands arrive as
  input packets and run through the same station code as the host's own input (per-player context).
- Sync of a moving aircraft (the key requirement): crew positions never live in world coordinates.
  Every crew pose (own and others') is kept and sent in the aircraft's model frame, and the camera is
  aircraft pose x local eye. So however the aircraft is interpolated, the cabin, your own body and the
  other crew move together; nobody slides out of the fuselage. Your own walking is simulated locally
  (no latency); the host trusts it (cooperative game) and applies seat locks.
- Aircraft and world state: host snapshots at 30 Hz (kinematics, controls, turrets, fighters, crew
  poses) and 5 Hz (engines, fuel, damage, bombs, stations), plus events (shots, flak bursts, hits,
  explosions, messages). Clients estimate the host clock (min-delay filter over pings) and render
  100 ms in the past, interpolating position with velocity (cubic Hermite), attitude with slerp, turret
  angles and fighters; short gaps are extrapolated (up to 250 ms). WebSocket over TCP is enough: each
  snapshot is complete, so a late one is simply superseded, and the 100 ms buffer hides the occasional
  retransmit stall. Compressed with permessage-deflate.
- Measured in tests (net_test.ts): interpolation error against the true path for a manoeuvring bomber
  with jitter and loss; browser test with a host and a client page.
